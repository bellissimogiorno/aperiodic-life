# Rebuild the complete catalogue

The checked-in `aperiodic-life-catalogue.pdf` covers all 89 curated configurations,
all 12 named rule-selector templates and all 56 complete rule-sets used by the
configurations. It is a computational catalogue with qualified attribution, not
a claim that every package search result is a world-first discovery.

AI generated following prompts by Murdoch J. Gabbay.
Catalogue documentation revision 2, 14 October 2026, accompanies release 3.7.4.
This revision names the source of each adaptation and separates direct sources
from background literature, with linked rule identifiers and numbered references.
Application release 3.7.5 retains this reviewed 3.7.4 catalogue, including its PDF,
editable prose, metadata, data and geometry. The application and catalogue
versions are recorded separately in the handover manifest and download names.

## Editable source

- `catalogue.md` is the actual editable prose source. Keep its `##` keys and `###`
  headings: the builder reads these sections directly.
- `catalogue-source.json` holds the exact rules, seed records, measurements,
  attribution, references and catalogue identifiers. Rules and pattern credits
  are separate fields. Edit these deliberately when evidence changes.
- `geometry/diagrams.json` contains exact production snapshots, complete initial
  states, polygons, neighbourhood lists and hashes.
- `build_catalogue.py` lays out the document using ReportLab and attaches its
  machine-readable companion with pypdf. The bundled DejaVu fonts avoid dependence
  on fonts installed on the build machine; see `fonts/LICENCE.txt`.
- `export_geometry.js` regenerates the 267 illustrations from the application.

From the repository root, with Python 3.10+:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r docs/catalogue/requirements.txt
.venv/bin/python docs/catalogue/build_catalogue.py
```

On Windows use `.venv\Scripts\python.exe` for the last two commands. Documentation
dependencies are optional: running the browser app and the normal JavaScript
tests does not require ReportLab or pypdf.

The command writes the PDF and `catalogue-data.json` beside the source. The latter
is also attached inside the PDF; it contains the full seed data even where a long
seed is not typeset. Temporary PDF pages are created in a temporary directory and
removed afterwards. `--output PATH` writes the PDF elsewhere; `--check` checks
coverage, source hashes, specifications and narrative sections without writing.

To regenerate the figures after a deliberate seed/engine change:

```bash
node docs/catalogue/export_geometry.js
node research/verify-catalog.js
node docs/catalogue/verify_credited.js
python3 docs/catalogue/build_catalogue.py
```

The catalogue builder detects stale `core.js` or `discoveries.js` hashes and
requires its exact source metadata to agree with the snapshot export. Update
`catalogue-source.json` only after reviewing changed evidence and regenerate the
figures. It deliberately does not silently replace scholarly annotations.
The catalogue may accompany an application with the same major and minor version
and an equal or later patch version. Its geometry must still match the catalogue
version exactly, and both recorded hashes must still match the current engine and
preset source. An application patch never bypasses these evidence checks.

To check the retained source and the catalogue validation regressions without
regenerating the PDF, run with the optional documentation dependencies installed:

```bash
python3 docs/catalogue/build_catalogue.py --check
python3 test-catalogue.py
```

These optional checks are separate from the standard test profile so the app's
normal checks continue to work without ReportLab or pypdf.

## Review and attribution

Run the full preset verifier and the specialised evidence checks named in each
entry; render the rebuilt PDF and inspect every page. Internal links and fonts
are embedded. Each pattern page identifies its source, its complete rule and the
scope of the evidence. “Original to this package” identifies a configuration
generated by the package search for which no exact precedent was identified in
the literature reviewed as at 14 October 2026. It does not establish worldwide
first discovery. P09 has a possible published antecedent and is not claimed
original. Rule origin is stated separately from pattern origin.

The release contains finite-board R-pentomino and Acorn runs. Their late states
must not be confused with the unbounded-plane benchmarks. The catalogue states
this limitation explicitly.

The PDF does not embed its own containing release ZIP. The checked-in data,
reproduction instructions and hashes provide provenance without a circular
archive dependency. GitHub Pages staging includes this directory so that the
About links work at a repository subpath as well as from an extracted release.
